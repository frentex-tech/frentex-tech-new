## 1. Executive Summary of Routing Architecture

The Frentex Tech website is implemented as a localized static export application in Next.js 15 App Router. The site targets a dual-language structure:
- **Default Locale:** Arabic (`ar`, RTL, dir="rtl"), served at root paths (e.g., `/`, `/services`, `/work`).
- **Secondary Locale:** English (`en`, LTR, dir="ltr"), served under the `/en/` prefix (e.g., `/en`, `/en/services`, `/en/work`).

### Key Route Architecture Patterns & Discrepancies
1. **Dynamic Query Routes vs. Static Segments:**
   - Case studies / demos use a single route (`/project` and `/en/project`) with a dynamic query parameter (`?project=crm`, `?project=ops`, `?project=erp`).
   - While functional via client-side `useSearchParams()`, search engine indexability and social sharing are compromised because static export generates a single `project.html` and `en/project.html`. Search engines crawling without JavaScript will only receive the fallback/default stage.
2. **Static Export Canonical Extensions:**
   - Canonical URLs on several inner routes are output with `.html` suffixes (e.g., `https://frntextech.com/en/services.html` and `https://frntextech.com/en.html`), while primary Arabic routes omit the extension. This creates an asymmetric indexing footprint and requires specific web server rewrites.
3. **Dead / Orphan Components Detected:**
   - `src/components/WorkLab.tsx` (101 lines): completely unused legacy implementation superseded by `WorkLabShowcase.tsx`.
   - `src/components/visual/solutions/ServicesEcosystem.tsx` (249 lines): orphaned visualization component not referenced by any route.

## 3. Discrepancies, Gaps & Architectural Vulnerabilities Found

### 3.1 Dynamic Query Parameter Routes vs. Next.js Static Export
- Routes `/project?project=crm`, `/project?project=ops`, `/project?project=erp` and their English equivalents rely strictly on `useSearchParams()`.
- **Architectural Gap:** Because `output: "export"` generates only a single static file (`project.html` and `en/project.html`), social sharing scrapers and search bots that do not execute client-side JavaScript will only see the default stage (`crm`), ignoring `ops` and `erp` entirely.
- **Remediation Recommendation:** Convert `/project?project=:slug` into static path segments `/project/madar-crm`, `/project/sayr-ops`, and `/project/raseed-erp` using Next.js `generateStaticParams()`.

### 3.2 Canonical URL Inconsistency (`.html` Suffix vs. Clean URLs)
- Noticeable asymmetry across the route inventory:
  - Root route canonical: `https://frntextech.com/` (Clean).
  - English homepage canonical: `https://frntextech.com/en.html` (Has `.html`).
  - Inner routes canonical: `https://frntextech.com/services.html` (Has `.html`).
- **SEO Risk:** When deployed to production CDN hosts (e.g., Cloudflare Pages, Vercel, Netlify) that default to clean URLs without `.html`, this will create self-referential canonical mismatch loops and duplicate content penalties unless strictly aligned.

### 3.3 Dead & Orphan Components
- `src/components/WorkLab.tsx` (101 lines): Replaced by `WorkLabShowcase.tsx` but left in the active source tree.
- `src/components/visual/solutions/ServicesEcosystem.tsx` (249 lines): Left abandoned after `ServicesHeroStage.tsx` was implemented.
- These unused files clutter the bundle analysis and confuse ongoing maintenance.
